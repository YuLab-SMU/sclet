+ **An anonymized group code had no documented way back to its label.** Every group reaching an evidence node is anonymized to `cluster_N` by a positional rule (`paste0("cluster_", seq_along(unique(<column values>)))`), and nothing said how to reverse it -- so the M11 report could only write "the terminal-state codes were not mapped back to alpha/beta/delta". Checking before changing anything showed the coding is correct: on the pancreas object `cluster_7` really is `Ngn3 low EP`, the root the plan asked for. What was missing is the reading rule, now in the provenance skill: index the same vector the record used (`levels(factor(as.character(object[[col]])))[N]`, with `col` taken from the record's own `inputs$group`), and two prohibitions -- a code must never be carried across objects (subsetting or re-levelling moves the mapping), and a code is not a cell type, so a resolved label has to be labelled as resolved because the node itself carries only the code. Pinned by a round-trip test. One suspected defect was checked and dismissed rather than "fixed": `n_reductions_written = 0` is right, because scVelo returns no velocity embedding and `VelocityPlot()` computes one at plot time via `embedVelocity()`.

+ **A re-run used to leave a stale evidence node behind, and seven recorders did it.** Found while auditing whether everything the loops surfaced had actually been fixed, which it had not -- this one was never in the backlog. An evidence node's id is derived from the analysis name (`ev:doublet_doublet_finder`), so running the same action twice reproduces it; `RecordAIEvidence()` refuses the duplicate, and **every** recorder wrapped that call in `tryCatch(error = function(e) object)`, so the second run returned an object whose `colData` said 0 doublets while the citable node still said 150. scDblFinder is stochastic, so two runs genuinely differ (4 then 2 on the test fixture): the node kept describing the first run and looked like a measurement of the current object. A stale node is worse than a missing one -- it is citable, it renders, and nothing warns. One shared function now decides between the three honest outcomes: identical values are a no-op; different values without `replace = TRUE` raise `evidence_id_conflict` naming both runs; `replace = TRUE` refreshes. Doublet, CNV, milo, velocity, trajectory, fate, enrichment, communication, route-comparison and malignant recorders all route through it, and `test-ai-evidence-rerun.R` asserts each one's routing, so a new recorder that forgets is caught. One test had to be rewritten because it pinned the bug: `test-ai-interpretation-gaps.R` asserted that a second real run "must degrade to a no-op in the recorder", which is exactly the stale citation.

+ **M6 (differential abundance, and the two defects that only a first execution could find).** `run_milo` was the one single-cell action the benchmark coverage table still listed as `none`, so this loop was its first execution anywhere -- and it died twice. + **Four provenance defects, found by driving the shipped skills against real data instead of fixtures.** The run was the external-agent path (`inst/skills/*`, no aisdk) over PBMC 10k -- 33,538 genes x 11,769 cells, a two-round plan held together by the ledger fingerprint -- and each defect corrupted an artifact rather than a log line, which is why none of them had failed a test. (1) **The marker evidence node recorded thresholds the run was not given.** `ExecuteAIPlan()`'s `run_de_test` handler carried `p_thresh <- 0.05; fc_thresh <- 0.1` as constants, so a plan asking `logfc.threshold = 0.25, min.pct = 0.1` produced a node reading `logfc_threshold = 0.1` with no `min_pct` at all: the artifact described a different analysis than the one that executed, and it is the artifact findings are graded from. The handler now resolves `min.pct`/`logfc.threshold` once, passes those same values into `RunDEtest()` and records them, adding `min_pct` to the bounded values, so the default path records `0.01`/`0.1` and a tuned path records what it asked for. (2) **An internal `.dimred` reduction survived every run.** `FindNeighbors()` routed its dimension subset through `set_dimred()`, which wrote `reducedDim(object, ".dimred")` and never removed it, and `RunUMAP()` did the same inline; after a plain pipeline `reducedDimNames()` was `c("PCA", ".dimred")`, the stray entry an 11,769 x 30 duplicate of `PCA[, 1:30]` visible to every later step that enumerates reductions. `set_dimred()` is deleted -- `FindNeighbors()` hands `makeSNNGraph()` the subset directly, with the graph pinned equal to the manual construction -- and `RunUMAP()` drops the scratch reduction immediately after `scater::runUMAP()`. (3) **`run_enrichment` chose the annotation database for the user.** A plan with no `db` validated and the handler applied `%||% "GO"`, although GO and KEGG use different universes and statistics and every sibling action with such a choice (`run_cci` `method`, `run_milo` design roles, `run_annotation` `ref`) refuses to run without it -- so the earlier entry's claim that "`run_enrichment` never picks the database" was not true of the AI path. + **Second audit of the CNV layer: two crash-level defects and three silent ones, all about how a value is obtained rather than how it is used.** (1) A `gene_order` sharing no gene id with the object crashed with `replacement has 1 row, data has 0`, because the `chr` column was normalised after filtering to zero rows; gene-id mismatch (ENSG vs symbol) is the ordinary route to it, so normalisation now precedes subsetting and no overlap is a named error printing both id styles. + **Audit of the phenotype evidence framework: two promises were broken while every test still passed.** Both defects sat in the *meaning* of the result rather than in its mechanics, and neither was a boundary case. (1) The competing-hypothesis test was circular: it defined "the cells under discussion" as those whose call was `supported`/`probable`, but the signature is what selected those cells, so the competing programme was guaranteed to separate them and the question answered itself. Worse, the demotion swept `refuted` cells into `undetermined`, so a refusal could be overturned by the very check meant to challenge affirmative calls. Groups are now defined by the *evidence* (`in_scope` = at least one line positive, `residual` = none), never by the call, and `refuted` is never demoted. (2) Independence rested on declaration alone: registering one measurement under two names made every cell `supported`. The registry cannot see inside a provider, but it can honour a declaration -- providers sharing a `source` now count as ONE line, and re-registering an existing name is refused instead of silently replacing it. Three smaller defects are also fixed: `n_cnv_regions` was written to `colData` and the state record but never computed (a promised measurement that did not exist) and the column is gone; a non-count assay was coerced with `mode(x) <- "integer"`, truncating every value silently, and a negative or non-integer assay is now refused with a pointer at `counts`; and the generic-to-malignant mapping had two overlapping rules that agreed only by evaluation order. + **Phenotype evidence as a registry, with the malignant call as its first instance.** The malignant-cell layer above hard-coded inferCNV as "the second line", which was a design defect rather than a missing generalisation. `PhenotypeEvidenceProviders()` now holds named providers (a plain list of `available()`, `decide()`, `dependence`), so a caller registers their own without subclassing anything, and `CallPhenotypeCells()` turns the providers into a four-state call -- `supported` (two or more positive), `probable` (one), `undetermined` (conflict, nothing usable, or a competing programme explains the split) and `refuted` (an explicit negative and no positive). Three rules keep the answer honest. First, `dependence`: a line computed from the same expression matrix as the signature is `shared_with_signature` and cannot count toward `supported`, which is precisely the property the iterative method lacks when it re-derives its own signature. Second, *missing is not negative*: a low signature score means the line did not fire, not that the phenotype is absent, so only a provider that says `negative` counts as a no -- a signature-negative cell with one positive provider is `probable`, and `refuted` requires an explicit negative. Third, claims reuse the package's existing ladder (`observed` -> `measured` -> `associated` -> `consistent_with`) instead of introducing a second vocabulary for confidence, and nothing reaches `observed`, because a per-cell label is never a direct observation of cell state. The iteration from the reference method is deliberately absent here: it is appropriate when the cell population itself is unknown, and a call built on named evidence is not improved by re-deriving its own signature. `CallMalignantCells()` becomes thin -- it names the CNV provider, maps the generic call onto the malignant vocabulary, and now requires a CNV record instead of silently degrading to a signature-only call. Verified by `test-phenotype-evidence.R` (30 assertions), including that three registered shared-matrix providers still cannot manufacture a two-line call; full suite 653 tests / 0 failures / 5882 passed.

+ **Malignant-cell identification: a reference port and a two-line call.** Issue YuLab-SMU/ProjectYulab#26 asks for the iterative malignant-epithelium classification of Zhang et al. (*Gut* 2020, doi:10.1136/gutjnl-2019-320368); its third comment, reproducing the method, argues from the paper's own supplementary tables that the iteration separates **gastric from intestinal identity** rather than malignant from benign, that the malignant rate moves from 30.6% to 6.6% when only the seed source changes, and that after the first round the "non-malignant" pool contains tumour-sample cells so the baseline is no longer the normal samples. All three are structural consequences of the algorithm: k-means always returns two groups, re-deriving the signature from the split is positive feedback, and the reference is endogenous. Three additions follow from that. (1) `FindMalignantSeedGenes()` and `ClassifyMalignantEpithelium()` port the published procedure as a **baseline** (`method = "iterative"`), reporting diagnostics instead of a verdict; writing it surfaced three failure modes, each now named and tested: `AddModuleScore` control bins collapse every score to 0 when the scored matrix holds only signature genes (so scoring runs against the full feature set with both signatures excluded from each other's controls); k-means splits any population, so a 55/5 fixture came back 92/8 and is reported as `split_degenerate` with a warning rather than as a classification; and a flipped k-means assignment is the same partition, so agreement is `max(same, swapped)/n` because the raw diagonal would read it as 0% and the loop would never stop. (2) `check_cnv_readiness()` and `RunCNVInference()` add **copy-number evidence from inferCNV against an exogenous reference** -- normal cells named by the caller, never cells the algorithm classified -- which cannot drift with the split; when inferCNV or its JAGS system library is absent the run records `status = "unavailable"` and writes `NA`, never 0, so an absent measurement cannot read as a negative result. One measured defect is pinned against a real inferCNV object rather than a synthetic one: inferCNV's `expr.data` is reference-centred and hovers near 1 for every cell, so `colMeans(abs(expr))` measures the baseline and separates the malignant and normal groups of inferCNV's own bundled example by **-0.005**; subtracting each cell's own median first leaves the profile shape and separates the same groups by **+0.038**. (3) `CallMalignantCells()` is the package's answer (now a thin facade over the generic layer described in the next entry): a **four-state call** -- `malignant` (both lines positive), `likely_malignant` (exactly one), `undetermined` (conflict, CNV unavailable, or a competing identity programme explains the split) and `non_malignant` (neither) -- so disagreeing evidence is never resolved by majority and a one-line call is never read as a two-line one. Its `identity_genes` argument makes the issue's central criticism operational: a suspected competing programme that separates the evidence-positive sides demotes those cells and says so. The CNV cutoff must sit strictly above the reference maximum, because a constant or exactly-measured reference sits on its own threshold once `mad = 0`. Neither state nor cutoff is a discovered truth: both are analysis parameters, and the documentation says to report the state distribution and the disagreement cells alongside any conclusion. Verified by `test-malignancy.R` (39 assertions) and `test-malignancy-cnv.R` (25). Design notes in `notes/malignant-cells-2026-10-18.md`.

+ **Plan repair loop**: `AIPlanAnalysis()` gains `max_repair_rounds` (default `1L`, allowed `0:3`). When the first proposal fails `ValidateAIPlan()`, the verbatim validation errors are fed back to the model as a repair prompt and it is asked to propose a corrected plan, up to the requested number of rounds. + **Integration Workflow**: Added `RunIntegration()` as a unified entry point for multi-backend data integration, currently supporting `fastMNN` and `Harmony`. Downstream functions like `FindNeighbors` and `RunUMAP` can now automatically perceive and consume the integration states.
+ **Reference Mapping**: Added `RunKNNPredict()` and `RunReferenceMapping()` for lightweight label transfer based on `BiocNeighbors::queryKNN`. Added `ProjectionPlot()` for query-reference visualization.
+ **DE & Enrichment**: Added `RunDEtest()` (wrapping `FindMarkers`/`FindAllMarkers`) and `RunEnrichment()` (wrapping `clusterProfiler`). Included corresponding visualization tools: `DEtestPlot()` (volcano plot) and `EnrichmentPlot()` (dotplot).
+ **Visualization Ecosystem**: Enhanced visualization capabilities by leveraging the `ggsc` package. Added `CellDimPlot()`, `FeatureDimPlot()`, `GroupHeatmap()`, and `CellStatPlot()`.
+ **Technical Debt & Bug Fixes**:
  - Migrated to `scrapper::aggregateAcrossCells.se` for pseudobulk aggregation and `scrapper` for HVG selection to eliminate deprecated warnings from `scuttle` and `scran`.
  - Fixed missing dependencies (`enrichplot`, `scran`) and non-ASCII character warnings, achieving a clean `R CMD check` (0 errors, 0 warnings, 0 notes).
