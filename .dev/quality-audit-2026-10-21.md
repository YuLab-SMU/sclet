## 缺陷 2：R/ 的 roxygen 源落后于已提交 man/（9 个文件）——文档会回退

在 `/tmp/roxy-probe` 副本上跑一次 `roxygen2::roxygenise(".")` 的结果：
`DESCRIPTION` **无变化**、`NAMESPACE` **无变化**、`man/` 9 个已跟踪 Rd 被改写、
29 个新 Rd 生成、**0 个被删除**。

但那 9 个改写是**减法**——roxygen 源比已提交的 Rd 旧，roxygenise 会把 Rd 里
较新的 @param 描述删掉。最小实证：`RunDEtest()` 的签名有 `group = NULL,
covariates = NULL, min_cells = 10L`（`R/markers.R:178`），而它的 roxygen 块
只写了 `object` / `ident.1` / `ident.2` / `name` / `...`（`R/markers.R:171-175`）；
已提交的 `man/RunDEtest.Rd` 里那三个参数的说明是**手加的**。

后果：直接 roxygenise 会让 `R CMD check` 的 codoc 报
`Undocumented arguments in documentation object 'RunDEtest'`——把现在通过的
检查变成失败。

**修法**：`.dev/tools/fix-roxygen-drift.R` 把已提交 Rd 的参数说明回填进 roxygen 源。
它区分两种漂移：源里**缺** `@param`（RunDEtest 丢了三个）和源里有但**描述更薄**
（CallMalignantCells 丢了 35 行细节）。判据是长度差 ≥25 字符——实测纯标记差异
只差 6–8 字符，真正的内容丢失差 60–260。

**验收**：修复 + roxygenise 后，9 个 Rd 的参数集合**无缺失**，且
**min_expr / cutoff 两处已丢的文档被补回**；剩余差异只有措辞与 `\code{}` 标记。

## 缺陷 3：29 个手写 Rd 被 roxygen2 永久跳过 + 10 个 alias 重复

这些 Rd 缺 `% Generated by roxygen2` 头，roxygen 报
`Skipping <name>.Rd -- It already exists and was not generated by roxygen2`，
**永远不重新生成**——手改 Rd 不会被下次 roxygenise 覆盖，roxygen 源里的改动
也永远进不了 Rd。

其中 `man/advanced-ai-diagnostics.Rd` 与 10 个按函数分页的 Rd 声明同一批 alias，
roxygenise 报 *Aliases documented in multiple Rd files*。

**修法**：备份到 `.dev/backup-handwritten-rd/`，删除，让 roxygen 接管。
**验收**：0 个导出函数失去文档，10 个 alias 重复归零，276/276 个 Rd 带 roxygen 头，
roxygenise 输出**无 `Deleting '<name>.Rd'`**。

## 缺陷 5：随机性函数没有 seed，状态里也不记

| 函数 | 随机性 | seed 参数 | seed 记进状态 |
|---|---|---|---|
| `FindClusters()` | igraph Louvain 打破平局 | 有 | 有 |
| `RunMilo()` / `refit_milo()` / `RunSlingshot()` / `RunSCENIC()` / `RunRegVelo()` | 有 | 有 | 部分 |
| **`RunUMAP()`** | **uwot 随机初始化** | **无 → 已补** | **无 → 已补** |
| **`RunIntegration(method = "Harmony")`** | **harmony 随机初始化** | **无 → 已补** | **无 → 已补** |
| **`RunIntegration(method = "scVI")`** | **Python 训练随机** | **无 → 已补** | **无 → 已补** |

`FindClusters` 的现成注释就是这件事的代价（`R/clustering.R:105-108`）：
> 2026-10-19 两次跑同一个 plan，PBMC 10k 上分别得到 13 和 12 个簇。

**整改**：新增内部助手 `sclet_with_seed(seed, expr)`（`R/state.R`），存/恢复
`.Random.seed`——不是裸 `set.seed()`，因为裸调用会静默移动用户的 RNG 流。

**一个容易漏的细节**：`scater::runUMAP()` **不吃 R 的 `.Random.seed`**。
实测：同一个对象两次 `scater::runUMAP()` 结果不同，外层 `set.seed()` 也不起作用；
必须把 seed **透传给 uwot**（`uwot::umap` 自带 `seed` 参数）。
`RunUMAP()` 因此同时做两件事：传 `seed` 给 uwot，外层用 `sclet_with_seed` 兜底。

**验收**（`tests/testthat/test-seed-discipline.R`，12 个断言全绿）：
```
user RNG stream preserved: TRUE
seeded value reproducible: TRUE
```

## 缺陷 6：`sclet_copilot` 有两个定义，靠 Collate 顺序决定谁生效

`R/ai-functions.R` 定义了 3 参版，`R/copilot.R` 定义了 5 参版。
DESCRIPTION 的 Collate 把 `ai-functions.R` 排在 `copilot.R` **前面**，
R 保留最后一个定义，所以运行时生效的是 5 参版——而 `ai-functions.R` 的注释
声称 "This definition is collated after the legacy copilot.R"，**与事实相反**。

已删除死定义。`man/sclet_copilot.Rd` 与运行时行为本来是一致的，删掉的是隐患：
Collate 顺序一变，用户拿到的签名就静默变了。

### 工具自身被修掉的三个 bug（都是被 agent 的反馈逼出来的）

1. **例子提取在 `\dontrun{}` 处被截断**——用"第一个以 `}` 开头的行"当
   `\examples{}` 的结束，但 `\dontrun{}` 的闭合括号也在列首。修法是按花括号
   深度计。修之前，`\dontrun{}` 块**之后**的代码从未被检查过。
2. **符号 linter 对含 `\dontrun` 的例子是瞎的**——`\dontrun{` 不是合法 R，
   `parse()` 失败后两个 walker 都返回空，于是对**每个** dontrun 例子都报
   "no undefined symbols"。修法：解析前把 `\dontrun{` 归一化成 `if (FALSE) {`。
   （ex-domain 发现，报告里点出了 5 个同类真缺陷。）
3. **分区脚本用 Rd 文件名反推对象名**——`subset-cell.Rd` 文档的是 `subset_cell`，
   `@rdname` 主题页覆盖多个函数。修法：从 Rd 自己的 `\name` / `\alias` 解析。
