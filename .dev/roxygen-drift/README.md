# roxygen 漂移报告（2026-10-21）

在 `feature/quality-2026-10-21` worktree 上，`roxygen2::roxygenise(".")` 的一次
**只读探针**跑出来的结果（副本在 `/tmp/roxy-probe`，未污染 worktree）。

探针结论：

- `DESCRIPTION` —— **无变化**（Imports / Collate 都已是 roxygen 管理的形态）
- `NAMESPACE` —— **无变化**（导出面与已提交状态一致）
- `man/` —— 9 个已跟踪 Rd 被改写，29 个新 Rd 被生成，0 个被删除

## 缺陷 1：R/ 的 roxygen 源落后于已提交的 man/（9 个文件）

新政策是"让 roxygenise 重新生成并提交"。**但直接跑会丢文档** —— 因为
roxygen 源比已提交的 Rd 旧，roxygenise 会把 Rd 里较新的 @param 描述删掉。

| Rd | 被删除的行数 | 丢了什么 |
|---|---|---|
| `man/CallMalignantCells.Rd` | 35 | `cnv_id` 降级语义、`cnv_cut` 推导方式、`identity_genes` / `identity_demote` 的完整语义 |
| `man/CallPhenotypeCells.Rd` | 12 | 参数语义 |
| `man/FindClusters.Rd` | 5 | 参数语义 |
| `man/FindMalignantSeedGenes.Rd` | 5 | 参数语义 |
| `man/GetAnalysisLedger.Rd` | 1 | 参数语义 |
| `man/PhenotypeEvidenceProviders.Rd` | 4 | 参数语义 |
| `man/RunCNVInference.Rd` | 4 | 参数语义 |
| `man/RunDEtest.Rd` | 9 | **`group` / `covariates` / `min_cells` 三个参数的整段说明** |
| `man/sclet-package.Rd` | 1 | 段落 |

已实证的最小案例：`RunDEtest()` 的**函数签名有** `group = NULL, covariates = NULL,
min_cells = 10L`（`R/markers.R:178`），但它的 roxygen 块**只写了** `object` /
`ident.1` / `ident.2` / `name` / `...`（`R/markers.R:171-175`）。

后果：如果不先修 roxygen 源就 roxygenise，`R CMD check` 的 codoc 会报
`Undocumented arguments in documentation object 'RunDEtest'` —— 把现在通过的
检查变成失败。

**修法**：先把这 9 个函数的 roxygen 块补齐到 Rd 的水平，再 roxygenise。
完整 diff 在 `stale-roxygen-diff.patch`（301 行），是权威依据。

## 缺陷 3：29 个手写 Rd 会被 roxygen2 跳过

这些 Rd 缺 `% Generated by roxygen2` 头，roxygen 报
`Skipping <name>.Rd -- It already exists and was not generated by roxygen2`，
永远不重新生成。它们是**永久漂移源**：手改 Rd 不会被下次 roxygenise 覆盖，
而 roxygen 源里的改动也永远进不了 Rd。

按新政策（"A hand-written Rd is therefore a permanent source of drift; delete
it once so roxygen takes ownership"）这 29 个应该删掉让 roxygen 接管。

2. 删掉这 29 个 Rd

5. 验证：重新生成的 Rd 内容 ⊇ 备份的 Rd 内容（逐个 diff）
