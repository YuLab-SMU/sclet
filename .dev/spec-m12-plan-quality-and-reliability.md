# Spec: M12 — 让「计划好不好」变成可测量，并把可靠性接进流程

Status: draft（2026-10-21 起草，未实施）
Baseline: `55d6523`（`make check` 0/0/0；AI 套件 FAIL 0）
上游共识: 本文档承接 2026-10-21 对话中确认的「可靠性定义」，见 §1.2。

---

## 1. 问题，以及为什么现在做

### 1.1 已建成的部分不再是瓶颈

M1–M11 把单细胞主干推到了「12 个域都有真实数据闭环、每份报告都能由独立进程只读账本复算
（8/8–13/13）」的状态。33 个注册动作全部有执行记录（6 个是 spatial/multimodal 的 typed
refusal）。**动作级和闭环级都不再是缺口**，继续补闭环的边际收益在下降。

剩下的两个问题都在**测量**层，而不是能力层：

**问题一：规划可靠性只有一个点估计，没有分母。**

`sclet-benchmark-ai/docs/action-coverage.md` 记录：同一个 Kang goal 跑九次、跨三个 commit，
**5 次出合法计划并完成，4 次死在计划形状上**。四个失败形状全部被 `ValidateAIPlan()` 正确
拦下，没有一次是引擎跑出错误结果；**合法计划执行成功率 5/5**。所以这是规划层，不是引擎层。

但这个 5/9 是**一次抽样**（9 次、3 个 commit、1 个 provider、树在变），不是一个比率。
任何 agent 用户拿到的是这九次里的某一次，他不知道自己这次落在哪边。**没有分母，
"可靠"就只是一句感觉。**

**问题二：能测「计划合不合法」，测不出「计划好不好」。**

九次 trial 里 5 次「成功」的判据是「合法且跑完」。一个稀松的、绕路的、或者漏掉关键探索
的计划，只要合法跑完也算成功。这正是「根据数据和阶段性结果规划好计划」「探索数据的价值」
现在**完全测不到**的地方。

### 1.2 可靠性定义（2026-10-21 确认，作为本轮及以后的验收口径）

> **可靠 ≠ 不出错；可靠 = 失败必须显性。**

三条判据：

1. agent 做错的每一步都被账本抓住；
2. 报告如实说出来（不润色成阳性结论）；
3. 独立进程只读账本可复算出来。

并且：**它没做的事，报告不会假装做了。**

骨架已由三件事撑起：`RenderAIReport()` 自检、复验脚本只读账本重算、claim ceiling 按最弱
证据定级。**本轮不重建这三件事，只把断掉的路接起来。**

### 1.3 本文档不解决的问题

- 不新增任何领域 action；
- 不提升模型能力，也不假设模型变强（§1.4 的天花板约束）；
- 不碰 ambient RNA / 多条件深度混杂 / 超稀疏这些**未跑过的数据形状**（那是另一个里程碑，
  见 §9）；
- 不测注释准确率（刻意留白，M5 已决定）。

### 1.4 天花板，写在这里以免验收时说不清收益来源

**prompt 这一层已经到顶**：证据引用覆盖率两轮修订纹丝不动（0.571 → 0.571，
17 次记录里 0.5–0.75 区间）。所以本轮**不靠加 prompt 提升计划质量**。

能靠我们这边做到的只有两件事：

1. **信息供给** —— 给模型更完整、更结构化的「当前数据能支撑什么、已经知道什么、
   还缺什么」。这是纯 R 确定性产物，不依赖模型变强。**本轮的收益主要来自这里。**
2. **回报信息质量** —— 校验错误从「你错了」改成「改成什么」。

不能靠我们做到的：让模型发现数据里没被设计测量过的东西。**验收时必须把收益写成
"上下文的判别力提高了"，不能写成"模型更聪明了"。**

## 2. 范围：五个子件

| 编号 | 子件 | 层次 | 预估 |
|---|---|---|---|
| M12-a | 建立分母：可靠性的重复测量 + 失败形状分类 | 测量 | 1 天（机时 1.5–2 h） |
| M12-b | 「好计划」的四维判据 + `data_support` 上下文 | 评估 | 2–3 天（大头） |
| M12-c | 回报信息质量：校验错误给「改成什么」 | 工程 | 0.5 天 |
| M12-d | skills 落地：知识型失败 + 四维判据 + 新字段 | 知识 | 0.5 天（含 pin） |
| M12-e | 报告接进流程：每轮结束必须渲染并自检 | 流程 | 0.5 天 |

依赖关系：**c 和 d 先于 a**（a 要记录失败形状，c/d 改了形状与报错才有意义）；
**b 是主体**；e 独立，可随时插。建议顺序 **c → d → b → e → a**，理由见 §8。

## 3. M12-a　建立分母

### 3.1 目标

把「5/9」升级为**带区间的比率 + 失败形状分类计数表**，格式在记录时就强制分类，
不允许事后人工归因。

### 3.2 做什么

1. **固定一条 goal 与一份数据**，在**同一棵树**上跑 N 次（N ≥ 12，建议 12）。
   用 Kang 的「比较刺激与对照、按 donor 配对」这条既有 goal，因为它是已知的中等难度样本
   （9 次里 5 成），太简单的 goal 会贴天花板、太难的会全是失败，都测不出区别。
2. **记录格式新增 `failure_class`**，取值必须来自一个封闭枚举，不允许 free text：

   | `failure_class` | 含义 | 层 |
   |---|---|---|
   | `none` | 只要计划通过校验且执行完成 | — |
   | `plan_empty` | 空计划 | 规划 |
   | `plan_shape` | 结构错（未知 action、未知 step 引用、`depends_on` 指向不存在步骤） | 规划 |
   | `plan_knowledge` | 结构合法但违反领域知识（占位符当值、顺序颠倒、用错参数词汇） | 规划 |
   | `plan_refused` | 计划合理但被 prerequisite gate 拒绝（`*_missing`、`counts_assay_missing`） | 规划 |
   | `execute_failed` | 计划合法但某步执行失败 | 执行 |
   | `report_unverifiable` | 跑完了但 `RenderAIReport()` 自检不通过 | 报告 |
   | `record_error` | 记录写入失败（`evidence_id_conflict` 等） | 记录 |

   分类规则：**取最靠后的那一层**。一个计划既空又被拒，记 `plan_empty`；跑完了但自检
   不过，记 `report_unverifiable` 而不是 `none`。
3. **每个失败必须附可机读的 evidence**：校验错误的 `code`、或自检区的失败断言名。
   **不允许只写描述**——描述是给人看的，`code` 是给统计看的。
4. **报告带 Wilson 区间**，不报裸百分比。

### 3.3 验收物

`notes/m12-reliability-record.md`（由脚本生成，不手写），包含：

- N 次记录表：每次一行（run id、commit、`status`、`failure_class`、`n_steps`、
  `n_findings`、引用覆盖率、耗时）；
- 汇总：成功率 + Wilson 95% 区间；按 `failure_class` 的计数；
- **一句话结论**，形式必须是「N 次里 K 次完成（X%，区间 [a, b]）；失败集中在 <形状>，
  其中 <哪些> 已在 <commit> 修掉」，**不允许写成单一平滑百分比**。

### 3.4 不做

- 不做多 provider 对比（会和 provider 变更混在一起，见 §3.5）；
- 不在树变动期间混跑（树变了要分批，批次必须写进表里）。

### 3.5 已知陷阱

`docs/action-coverage.md` 记过一次**记录纠错**：batch 1 的 `completed_rate = 1` 是因为脚本
读了 trial 的 `ok` 字段——`ok` 的含义是「写了记录」，不是「跑成功了」，非法计划也记
`ok = TRUE`。**新脚本必须按 `status` 计数，并且 `ok` 字段不进统计**。这个坑要写进脚本注释。

## 4. M12-b　「好计划」的四维判据（本轮主体）

### 4.1 设计约束

四条判据必须**都能从账本机读**，不靠主观打分。凡是需要人判的，写成"人工判定并附依据"，
且**不混进机读统计**。这是本文档最容易写歪的地方：一旦判据变成"看起来合理"，
这轮就退化成写观感。

### 4.2 四维定义

#### D1　目标覆盖（goal coverage）

**判据**：目标陈述里的每个分析意图，是否有对应的 action 覆盖；未覆盖的是否被**显式**记为
gap（写进 `success_criteria`、`evidence_gaps` 或 rationale）。

**机读来源**：`plan$goal` × `plan$actions` × `plan$success_criteria` ×
`ValidateAIPlan()` 的 goal coverage 检查结果。

**现状**：有骨架（`AIPlanAnalysis()` 的 goal coverage 修复、`sclet_ai_assess_success_criteria()`），
**但没有指标**。本轮把它变成一个数：`covered_intents / total_intents`，外加
`uncovered_but_declared`（漏了但有交代）与 `uncovered_silent`（漏了没交代，**这项才是问题**）。

#### D2　数据相称（data fitness）

**判据**：计划的规模与方法是否与数据形状匹配。这一维要**按数据形状给出不同的正确答案**，
而不是一套固定流程。

**机读来源**：`ledger$dataset`（n_cells、assays、reductions、columns）+
action `input_schema` 的 prerequires + `context$capabilities`。

**现状**：**部分是雏形**——prerequisite gate、`counts_assay_missing`、`ds_missing`
这些 typed refusal 已经是"数据相称"的判据，只是**散在各处，不成体系，也没有被计分**。
本轮把它们**聚合成一张表**，并补上现在没有的判断（见 §4.3）。

#### D3　阶段递进（round progression）

**判据**：第二轮之后的计划，是否**真的读了上一轮的报告**并据此改变；而不是把上一轮
重复一遍、或无视上一轮明确说出的警告。

**机读来源**：上一轮 `RenderAIReport()` 输出的 findings / warnings / limitations /
evidence_gaps，与本轮 plan 的 `actions`、`params`、rationale 做对照。

**现状**：**有通道没度量**。`analysis_story$user_decisions` 已经进 planning context 并实测
2/2 被使用；但"上一轮的警告改变了这一轮的动作"这件事，**从没被检查过**。

**具体判据**（每条都可判定）：
- 上一轮报告里有 `warnings` / `limitations`，本轮 plan 是否对其中至少一条作出回应
  （修掉它，或明确继续的理由）；
- 上一轮已经有某分析，本轮是否**重复执行同一个 action 且参数未变**（重复轮，应记为 `no_progress`）；
- 上一轮报告的 `evidence_gaps` 是否有对应动作被规划。

#### D4　信息增量（evidence increment）

**判据**：计划执行后是否产生了**新的**证据线（新的 `ev:` 节点），而不是把已知的又测一遍。

**机读来源**：执行前后 `GetAnalysisLedger()$state_records$ai_evidence` 的节点集合差集，
以及 `check_claim_ceiling()` 的 `n_independent_groups` 变化。

**现状**：**完全没有**。这是从零新增的一项，也是最直接对应「探索数据价值」的一项。

**规则**：零新增节点的计划**不判为失败**（有些轮次本来就是确认性的），但必须如实记为
`evidence_increment = 0`，并写进报告。**把"什么也没增加"说成"完成了"，正是可靠性定义
第 2 条要防的事。**

### 4.3 `data_support`：给规划上下文的判别性信息（本轮的收益所在）

现在 `analysis_story` 记的是**历史**（timeline、user_decisions、conflicts、
evidence_gaps），**不记数据现在能支撑什么**。模型要规划，只能自己从 `dataset` 字段
（assay 名、列名）反推，而这正是"知识型失败"的温床。

**新增一个确定性字段 `analysis_story$data_support`**，纯 R 侧计算，不含任何模型调用，
不含逐细胞值。字段形状：

```text
data_support:
  schema_version
  shapes:                      # 数据形状的事实（布尔，全部可从 dataset 推出）
    has_counts                 # 有 counts assay（velocity 的前提）
    has_spliced_unspliced      # 有 spliced/unspliced
    has_multiple_samples       # 某个列有 >1 个取值且像样本列
    candidate_design_columns   # 候选 batch / condition / donor 列名
    has_replicates             # 每个 condition 有 >1 sample（milo 的前提）
    has_spatial                # spatialCoords 存在
    has_multimodal             # altExp 存在
    has_epithelial_tumor_context  # 存在 CNV 相关的既有记录或肿瘤来源标注
  supports:                    # 由 shapes 推出的"能支撑什么"（带理由）
    - question_class: "velocity"
      supported: FALSE
      reason: "counts_assay_missing"
      unblocked_by: "提供 counts，或使用带 spliced/unspliced 的导出"
  blocked:                     # 现在做不了的动作及其 gate
  unconfirmed_semantics:       # 需要用户回答才能规划的选择（reference / batch / root）
  unexplored:                  # 数据里有、但账本里还没有结果的价值点
    - what: "donor × condition 结构存在，但没有差异丰度分析"
      action: "run_milo"
```

**`unexplored` 是这一节的核心**，也是「探索数据价值」的直接实现：它是**数据里有、
账本里没有**的东西。现在的 `evidence_gaps` 只记录"某个分析缺证据"，**不记录
"这份数据本来能做、但还没做"**。模型看不到这一项，就只能按固定 pipeline 走。

**约束**：
- 纯确定性，同 `analysis_story` 其余字段，同一对象两次调用结果必须一致（可 pin）；
- 不含原始值、不含受保护标识符（沿用 `sclet_ai_safe_value`）；
- `supports` 的 reason 必须引用**既有的 gate 名**（`counts_assay_missing` 等），
  不新发明词汇，否则模型记不住、技能层也没法写。

### 4.4 验收物

`notes/m12-plan-quality-report.md`，结构固定：

1. **一道题，两个答案**：同一份真实数据、同一个目标，**人工写的参照计划**与
   **agent 计划**并列（agent 计划取自 M12-a 的某一次记录，注明 run id）；
2. **四维逐条判定**：D1–D4 每维给出「判据 → 结果 → 依据（账本里的具体字段与值）」；
   机读项进表，需人工判的单独标注；
3. **差异说明**：agent 这里多做了什么、漏了什么、选错了什么，**逐条对应到具体 step**；
4. **结论**：本轮 `data_support` 上线前后，同一题的计划在 D2/D4 上是否改变。
   如果没有改变，照实写"没有改变"——**这不丢人，掩盖才是**。

另加一份**回归题库**（见 §4.5），因为它比任何主观评分都坚实。

### 4.5 回归题库：用 M1–M11 的已知答案当判据

M1–M11 留下了 12 个真实局面，每个都有**已知正确答案**。把它们写成可判定的判据，
就是「探索数据价值」的直接度量：

| 题库条目 | 局面 | 正确答案（来自既有闭环） |
|---|---|---|
| Q1（M7） | PBMC 10k，某群 98.3% 是双细胞 | 先去掉双细胞再解释该群，不要把它的组成当真 |
| Q2（M9） | 数据只有 logcounts、无 counts | **拒绝** velocity，不许在 Python 里跑崩 |
| Q3（M2） | Kang：stim 只在 batch2 | 把批次与条件混杂写成限制，不许当纯 condition 效应 |
| Q4（M10） | CNV 签名阈值取中位数 → 恰好一半阳性 | 认出这是定义不是生物学，指出阈值来源 |
| Q5（M5） | cluster 注释主导标签 0.22 | 标为混合，**不给类型** |
| Q6（M11） | 3 个终态、吸收概率 0.107/0.599/0.294 | 区分"终态细胞间占比"与"去向分布" |

每条的判定方式：**给 agent 该局面下的上下文（账本，不含答案），看它的计划/结论是否
落在正确答案上**。六条里过了几条，是一个可复算的数。**题库本身要能被 `make check` 之外
单独跑**，因为它需要真实数据对象。

## 5. M12-c　回报信息质量

### 5.1 目标

4 次失败里 3 种形状，每种都给出**具体改写建议**，而不是只说"你错了"。

### 5.2 做什么

按 `inst/skills/sclet-driver/SKILL.md` 现有的「Recovering from validation errors」四条定式，
把**知识型**失败补成同一形式（现状 + 改成什么 + 为什么）。至少三条：

| 现状 | 现在的报错 | 改后必须包含 |
|---|---|---|
| 模型写 `action = "not_run"` 来"删掉一步" | `action is not registered` | 明确：「删步骤是把该 step 从 `actions` 移除，并检查没有别的 step 的 `depends_on` 还指向它；不要写占位 action」 |
| 空计划（43k 细胞目标返回 0 步） | `plan_empty` | 明确：「目标含 N 类意图时，计划至少要为每类给出一个 action 或在 `success_criteria` 里声明不做；0 步意味着什么都没规划」 |
| 重复步骤去重误删依赖 | `depends on unknown step(s)` | 已修（`a8b1cc7`），但报错仍应指出**是哪一步、哪个 step_id 被删了**，因为下次还会有人撞 |

### 5.3 约束

**只改报错文字与 skill，不改校验逻辑。**校验的判定不变，本轮不放松也不收紧任何 gate。
pin：对每个改动的 `code`，断言错误信息包含该 `code` 与一句 `fix:` 指引。

## 6. M12-d　skills 落地

### 6.1 原则（沿用 AGENTS.md 已写明的架构规则）

> Skills 是注入的领域知识，引擎仍是权威。**知识型失败（顺序、参数词汇）进 skill，
> 不进 inline prompt。**

所以 4 次失败必须**分两类落点，不能混着写**，否则 skill 变成错误清单：

| 失败 | 类型 | 落点 |
|---|---|---|
| 去重误删依赖 | 引擎型 | 代码已修 + pin；**skill 不记** |
| `not_run` 占位 | 知识型 | M12-c 报错 + **skill 写正误对照** |
| 空计划 | 知识型 | M12-c 报错 + **skill 写明最少覆盖** |

### 6.2 三件事

1. **`sclet-driver`**：补「删步骤」「空计划」两条正误对照（与 §5.2 同一措辞）；
2. **`sclet-analysis`**：新增一节「什么算好计划」，写 D1–D4 四维判据，**并给
   "数据形状 → 探索顺序"的映射表**。这张表是 M12-b 的产出，也是「探索数据价值」的
   可执行形式。示例行：

   | 数据形状 | 先做什么 | 什么时候可以谈下一步 |
   |---|---|---|
   | 多 sample × condition，去重/QC 未做 | 先 `check_qc` + doublet，再确认设计 | 双细胞比例与设计都已记录 |
   | 有 counts + spliced/unspliced | 才可规划 velocity → trajectory → fate | counts 与 spliced 均确认存在 |
   | 有肿瘤上皮 + 参考细胞 | 先 CNV，再谈亚群与恶性判定 | 阈值来源（hmm / 参考分位）已记录 |
   | 某群主导标签 < 0.5 | 标为混合、不给类型 | 有独立证据（marker 或双细胞排除）才可给类型 |

3. **`sclet-provenance` / `sclet-driver`**：`analysis_story$data_support` 上线后，
   写明"规划前先读 `data_support$unexplored` 与 `data_support$blocked`"，否则模型不知道
   有这个上下文可读。

### 6.3 pin 要求

`options(sclet.ai.use_skills)` 是开关，改了 skill 没人发现它没生效是常态。所以**每条 skill
改动都要有 pin 断言"关键段落存在且被注入"**。落点：`tests/testthat/test-ai-skills.R`，
断言注入文本包含新小节的标题字符串。这是 AGENTS.md「没有 pin 的修复只是主张」的直接应用。

## 7. M12-e　报告接进流程

### 7.1 现状（按代码核过）

- `RenderAIReport()` 是**显式调用**的：输入「记录 id + 对象」，输出 Markdown，
  **不调模型、不含原始值**；不会自己触发。
- `RunAIAnalysis()` 只在执行成功后**可选**生成 report。
- 架构硬规则：**一个 plan 就是一个轮次；开始下一轮是调用方的事**（AGENTS.md）。
  `ExecuteAIPlan()` 不回写后续步骤；记录一轮会改变 fingerprint，旧计划被拒是**故意的**。

**结论：不会不断生成报告文件。账本在长（追加式日志），报告是账本的一个视图。**
M4 那次「单一报告来源」之后，`notes/` 里不再有手拼的报告。

### 7.2 要修的代价

**不渲染就没有自检，也就丢掉了"失败显性"那次检查。**而且下一轮该读的"阶段性分析结果"
应该是**过了自检的报告**，不是让模型去啃原始账本——账本越长，引用越不全，
这很可能就是引用覆盖率卡在 0.57 的一个来源。

### 7.3 做什么

把「每轮结束渲染」从可选变成**默认**，并在 skill 里写成固定次序：

```text
第 N 轮：plan → validate → execute → 记录
    → RenderAIReport()       # 默认执行，不再是可选
    → 自检通过？ 否 → 报告里如实写，且**不允许**以"本轮完成"进入下一轮
                 是 → 报告作为第 N+1 轮的输入
```

**只保留最新一份报告 + 历史归档**（归档进 `notes/archive/`，或只保留账本不保留文件——
倾向于后者：**账本才是源，报告随时可重渲染**）。

### 7.4 验收物

- 一条 pin 测试：`RunAIAnalysis()` 成功路径的返回值里带报告（或报告路径），且默认开启；
- 一条 pin 测试：自检不通过时，返回结构里能读出"未通过"标志，而不是静默；
- `sclet-driver` / `sclet-analysis` 里的流程段落与上面一致。

### 7.5 不做

**不做自动重规划**。一轮一个 plan 的规则不破；失败就报出来，由调用方决定下一轮。

## 8. 执行顺序与理由

**c → d → b → e → a**

1. **c 先做**（0.5 天）：报错文案 + skill 正误对照，最便宜，直接对应"不得心应手"；
2. **d 紧跟**（0.5 天）：知识型失败与四维判据进 skill——**因为模型读不到代码里的标准，
   只读得到 skill**；
3. **b（主体）**：四维判据的机读实现 + `data_support` + 回归题库。大头在 D3/D4 的判据
   设计与 `data_support` 的 shapes→supports 映射；
4. **e**（0.5 天）：接进流程，独立可插；
5. **a 最后**（1 天，机时 1.5–2 h）：**分母要在前四项之后测**，否则测出来的是旧树。
   违反这一点会让整轮记录作废。

## 9. 明确不做（留给下个里程碑）

- **真实脏数据的鲁棒性**：ambient RNA 主导、多条件深度混杂、超稀疏——需要新数据集，
  是独立里程碑（M13 候选），成本高于本轮；
- **多 provider / 多模型对比**：会和 provider 变更混在一起；
- **注释准确率**：继续不测；
- **B16（scVI 全量 43,095 细胞）与多 lineage fate fixture**：体力活，不属本轮；
- **提升证据引用覆盖率到某条线**：根因未定位前不承诺数字（§1.4）。本轮只做一件事：
  **把低值拆成可修的根因**（写进 M12-b 的结论第 4 条）。

> 本轮不加任何分析能力，只做两件事：**给"可靠"一个分母**（M12-a），**给"好计划"一套

## 12. 之后：M13 的方向（只写方向，细节等 M12 落地后再规划）

> 状态：**占位**。本节只固定"下一轮要回答什么问题、验收物长什么样"，不写实现细节。
> M12 做完后另起 `.dev/spec-m13-*.md` 写细节；本节的分歧点也要在那时重新核对一遍。

### 12.1 为什么 M12 之后还需要一轮

M12 测的全是**我们已经走过的地方**：9 次 replay 用的是同一个 Kang goal，题库 Q1–Q6 用的是
M1–M11 的**已知答案**。它回答的是「面对见过的局面能不能想对」，而"AI 功能差不多了"这句话
要求的是**「面对没见过的局面能不能想对」**。这两件事差得很远。

所以 M12 结束后，能说的话形如：

> "同一目标 N 次中 K 次完成（区间 [a,b]）；四维判据都有数；面对 M1–M11 的六个已知局面，
> 题目里过了 M 条。"

还**不能**说的话是："面对一份没跑过的脏数据，它能想对。"

### 12.2 M13 要回答的唯一问题

> **给一份从没见过、且脏的真实数据，agent 会不会做出 M12 之前不会做的判断？**

注意问法：不是"成功率会不会更高"，而是**"计划里有没有出现以前不会出现的判断"**。
成功率高可能只是把失败救回来，产出一样；**新判断才是能力**。

### 12.3 候选验收物（形态先定，内容待定）

1. **一份脏数据的完整闭环报告** —— 沿用 M1–M11 的验收物形态：真实数据 → 证据节点 →
   引擎评级 → `RenderAIReport()` → 独立进程只读账本复验。**唯一区别是数据不再是"顺路"的。**
2. **「新判断清单」** —— 逐条列出：这个判断**在 M12 的题库里没有对应项**，且**数据本身
   支持它**（附账本依据）。反过来也要列"agent 没做出的判断"，二者并列才诚实。
3. **与 M12 题库的对照** —— 在脏数据上 Q1–Q6 过了几条（应≥6 的既有水平），用来确认
   没为了"新判断"牺牲已知正确性。

### 12.4 候选数据形状（未定，按可获得性选）

| 形状 | 难在哪 | 为什么值得 |
|---|---|---|
| ambient RNA 主导 | 空滴与低质量细胞混在真实群边缘，双细胞与环境 RNA 难分 | 现有 gate 完全没有对应判据 |
| 多条件 × 深度混杂 | condition 与测序深度/capture 相关，任何"差异"都可能是指标伪影 | Kang 已碰过一半（stim 只在 batch2），但只标了警告 |
| 超稀疏（低 depth / 少细胞） | 稀疏 sampling 让 marker、velocity、milo 全部失真 | 现有 12 个闭环的数据都足够密 |
| 单样本多样本混合设计 | 一半条件有重复一半没有 | milo 的 replication gate 会部分拒绝 |

**选择原则**：优先选"现有 gate 会**拒绝**，而正确做法**不是**拒绝而是换个方法"的形状——
因为拒绝已经做得很好了（typed refusal 是这套系统最强的地方），M13 要测的是**拒绝之外**判断。

### 12.5 已知硬约束（M13 也绕不过去）

- **prompt 已到天花板**（§1.4）：不能靠加提示提升；若 M13 也证明瓶颈在模型侧，那就得动
  provider 或架构，而不是再写一轮 prompt；
- **CI 跑不了**：真实数据对象进不了 `make check`，验收物是 `notes/` 里的记录 + 单独脚本；
- **成本**：M13 单条闭环按 M1/M10/M11 的实际耗时估（半天到一天，含数据准备），
  比 M12 贵，且**可能一次跑不通**——M2/M6/M9 那次 9 个里程碑里 5 个中途挖出 claim 级缺陷，
  比例是常态，排期要按这个留余量。

### 12.6 明确不放进 M13

- spatial / multimodal 那 6 个 typed refusal 转正（那是 M14 量级，需要对应类型的数据）；
- 注释准确率（继续不测，M5 已决定）；
- 多 provider 横向对比（属独立测量，不与能力建设混在一轮）；
- 大规模 pathway / communication 的扩展（路线图 §5 仍暂停）。

### 12.7 与 M12 的接口

M12 必须留下的、M13 直接可用的东西：

| M12 产出 | M13 怎么用 |
|---|---|
| `failure_class` 枚举（§3.2） | 脏数据上的失败**必须**落进同一枚举；新增值要说明为什么现有八类不够 |
| 四维判据 D1–D4（§4.2） | 脏数据上的计划**用同一套判据评分**，否则两轮不可比 |
| `data_support`（§4.3） | 在脏数据上**首先检验它是否说谎**——这是它第一次面对没见过的形状 |
| 回归题库 Q1–Q6（§4.5） | 作为"已知正确性"的底线对照 |
| 每轮渲染 + 自检（§7） | 直接沿用，不重新讨论流程 |

**这条接口约束是本节最重要的一句话**：M12 的枚举和判据必须**留得下、用得上**，
否则 M13 又得重新造一套尺子，两轮的数字不能比。所以 M12-b 的实现在写的时候，
就要把"D1–D4 在任意数据集上都可计算"当成硬要求，而不是只在 Kang 上可算。
